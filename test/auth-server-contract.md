# Verification / appeals / reports Server contract

Contract source checked against the registered route implementations in `Server/server/routes/verificationApplications.js`, `appeals.js`, `reports.js`, and the route mounts in `Server/server/index.js`.

| SDK call | Server method/path | Authentication / authorization | Body or query | Success | Failure contract |
|---|---|---|---|---|---|
| `verification.getStatus()` | `GET /verification-applications/me` | required, not admin | none | `{application: object|null}` | auth errors; service unavailable 503; service error 500 |
| `verification.apply()` | `POST /verification-applications` | required, not admin | `{}` | 201 `{application: object|null}` | auth errors; duplicate/already verified/not found 400; unavailable 503 |
| `appeals.getStatus()` | `GET /appeals/me` | frozen session; frozen non-bot account | none | `{appeal: object|null}` | 403 for bot/non-frozen; unavailable 503 |
| `appeals.create()` | `POST /appeals` | frozen session; frozen non-bot account | `{description}` | 201 `{appeal: object|null}` | 403 auth/state errors; invalid/repeated submission 400; unavailable 503 |
| `reports.create()` | `POST /reports` | authenticated, frozen sessions permitted | `{target_kind,target_id,description,post_as_user_id?}` | 201 `{success,report}` | invalid kind/id 400; unavailable 503 |
| `reports.list()` | `GET /reports` | admin | `status`, `limit`, `offset` | `{reports: []}` | 403 non-admin; unavailable 503 |
| `reports.listAssigned()` | `GET /reports/assigned` | admin | `status`, `limit`, `offset` | `{reports: []}` | 403 non-admin; unavailable 503 |
| `reports.get(id)` | `GET /reports/:id` | admin | none | `{report}` | invalid id 400; missing 404; non-admin 403 |
| `reports.update(id)` | `PATCH /reports/:id` | admin | `{status,note,action}` | `{success,report}` | invalid id 400; non-admin 403 |
| `reports.resolve(id)` | `POST /reports/:id/resolve` | admin | assignment-specific `decision` or `actions` | `{success,report}` | invalid id 400; missing 404; non-admin 403 |
| `reports.retractTrust(id)` | `POST /reports/:id/trust-retract` | admin | `{reason,userId?,targetKind?,targetId?,reporterId?}`; reason must be at least 10 chars | `{success:true}` | invalid input 400; service 400/404/409; non-admin 403 |

**Legacy SDK-only routes:** `GET /verification-applications`, `GET /verification-applications/:id`, and `PATCH /verification-applications/:id` have no current Server registration. `VerificationAPI.list/get/update` were removed in SDK 0.2.0. The replacement moderation workflow uses `reports` and report IDs; direct application-ID interoperability is not established.

`auth-server-contract.test.js` verifies SDK request construction, bearer header, representative success response handling, and error propagation using a mocked fetch. This is a client contract test only: a mock does not prove that the Server registers/routes/authorizes the request or that service/database operations succeed. No live Server HTTP integration was completed in this isolated SDK test; Server auth and route behavior above was source-checked, not executed.

**HTTP execution boundary:** in `test/live-server-http.test.js` the isolated in-memory Server is exercised over HTTP by 13 of the 51 selected registrations. Auth (7 of 34): `GET /auth/providers`, `GET /auth/sessions`, `DELETE /auth/sessions/:sessionId` (404 path), `GET /auth/blocked-ips`, `DELETE /auth/blocked-ips/:ipHash` (400 path), `POST /auth/login-security/trust-current-ip`, and `GET /auth/me` (anonymous and invalid sessions rejected with 401; valid session returns a user payload). Users (6 of 6 selected): `GET /users/me/status`, plus `GET|PUT /users/:userId/status`, `POST /users/:userId/trust-moderation`, `PUT /users/:userId`, and `POST /users/:userId/note-outcome-retract` with anonymous/regular-user/admin separation. NyaitterAuth (0 of 11) is never exercised. The same run also covers all four verification/appeals registrations (`GET /verification-applications/me`, `POST /verification-applications`, `GET /appeals/me`, `POST /appeals`, including their 400 paths) and `POST /reports`, `GET /reports`, `GET /reports/assigned`, `GET /reports/:id`; `PATCH /reports/:id`, `POST /reports/:id/resolve`, and `POST /reports/:id/trust-retract` remain unexecuted. The remaining 21 auth registrations, every `nyaitter-auth` route, and exact response schemas beyond the observed assertions are source-checked only. The 34/34 auth and 11/11 NyaitterAuth request-path tests and 6/6 selected-user request tests use mocked `fetch`; they establish SDK serialization only. No real database was used.
